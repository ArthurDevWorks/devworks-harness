# Documentar um projeto legado

Gere ou atualize o contexto de engenharia a partir do código implementado. O
workflow é somente leitura no código; ele escreve exclusivamente os documentos
de contexto. Nunca use `.spec/` como fonte de verdade para descrever o legado.

## Segurança e propriedade

- Não leia `.env`, credenciais, tokens, chaves, cookies ou certificados. Use
  apenas nomes de variáveis presentes em `.env.example` quando necessário.
- Ignore `.git`, `node_modules`, `vendor`, `dist`, `build`, `coverage` e outros
  artefatos gerados, salvo quando forem a única evidência de uma ferramenta.
- Preserve arquivos manuais: só substitua `AGENTS.md`, `CLAUDE.md` ou
  `docs/agents/*.md` existentes quando trouxerem o marcador
  `<!-- Generated by /ai-context.` ou quando a pessoa solicitar `--adopt`.
- Em `--adopt`, migre regras concretas escritas manualmente para o contexto;
  não descarte conhecimento útil. Preserve blocos de ferramentas terceiras
  delimitados por tags XML em linhas próprias.

## Inspeção

1. Confirme que o alvo é um repositório Git.
2. Leia README, manifestos/lockfiles, configs, CI, testes, entrypoints,
   migrations/modelos, rotas/controladores e clientes de integração que existam.
3. Registre somente fatos sustentados por arquivos reais. Diferencie ausência
   de evidência de uma funcionalidade ausente.

## Saídas

Escreva a árvore abaixo no repositório alvo. Arquivos podem registrar “não se
aplica” desde que citem a evidência de ausência observada.

| Arquivo | Conteúdo |
|---|---|
| `AGENTS.md` | comandos, convenções, regras de comportamento, setup, referências e índice da documentação |
| `CLAUDE.md` | redirecionamento curto para `AGENTS.md` |
| `docs/agents/project_overview.md` | propósito, consumidores e fluxo macro |
| `docs/agents/architecture.md` | arquitetura, diretórios e integrações |
| `docs/agents/tech_stack.md` | linguagem, framework, runtime e testes |
| `docs/agents/coding_guidelines.md` | padrões observados e sua fonte de imposição |
| `docs/agents/domain_rules.md` | regras de negócio implementadas e seus arquivos |
| `docs/agents/api_contracts.md` | endpoints, autenticação, payloads reais e erros |
| `docs/agents/data_model.md` | entidades, armazenamento, relações e invariantes |
| `docs/agents/dependencies.md` | serviços, bibliotecas internas e infraestrutura |

Todo arquivo gerado inicia com seu título, linha em branco e este marcador na
linha 3:

```markdown
<!-- Generated by /ai-context. Manual edits are overwritten on re-run. -->
```

Os documentos em `docs/agents/` incluem `## AS IS — Current state` e terminam
em `## Related documents` com links para pelo menos 2 pares reais. `AGENTS.md`
termina sua parte canônica com `_End of AGENTS.md_`.

## Validação

```sh
test -f AGENTS.md && test -f CLAUDE.md
grep -Fq '<!-- Generated by /ai-context.' AGENTS.md
grep -Fq '## 6. Agent Documentation' AGENTS.md
grep -Fq 'AGENTS.md' CLAUDE.md
for f in docs/agents/*.md; do
  test -s "$f"
  grep -Fq '<!-- Generated by /ai-context.' "$f"
  grep -Fq '## AS IS — Current state' "$f"
  grep -q '^## Related documents' "$f"
done
```

Relate cada arquivo como criado, atualizado, inalterado ou ignorado por falta
de propriedade. Depois use `plan` para mudanças no legado; o `ai-context` não
planeja nem implementa a alteração.
